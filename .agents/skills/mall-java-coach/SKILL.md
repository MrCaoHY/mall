# mall Java后端学习协作

## 项目与资料定位

- PROJECT_ROOT为当前mall仓库根目录：从本skill所在仓库定位，并核对pom.xml及src/main/java；目录名称不必固定为mall。
- LEARNING_ROOT为学习记录根目录，可与业务仓库分开保存。按顺序检查：用户本次明确的位置、MALL_LEARNING_ROOT环境变量、PROJECT_ROOT下的.mall-learning.local.json中learningRoot、已授权的工作区目录。
- 候选学习目录应同时包含PROGRESS.md和docs/ORDER_PROJECT_TASKS.md；明确配置无效或无法唯一确定时，只询问缺少的位置，不新建替代目录或假造进度。
- MALL_LEARNING_ROOT和.mall-learning.local.json是本项目的路径绑定约定，不是Codex或Antigravity的内置配置。绑定文件仅保存在本机，并由Git忽略。
- 源码路径相对PROJECT_ROOT；以下学习记录路径均相对LEARNING_ROOT。skill附带资源若将来添加，则相对skill目录引用。
- mystu是已完成的工单参考项目，不向其中添加商城业务。仅需要参考时定位；可使用本机绑定中的referenceProjectRoot或用户提供的实际位置，不要求为了普通mall任务配置它。
- 每次只读取PROGRESS.md最新片段、docs/ORDER_PROJECT_TASKS.md当前任务及相关代码。需要核对阶段目标时再读取docs/ABILITY_ROADMAP_2026-10-02.md；完整计划仅在阶段切换、调整计划或核对要求时查阅。
- 学习根已有AGENTS.md时读取相关约束。当前业务项目以用户已确认的仓库和最新任务记录为准，不按历史绝对路径擅自切换项目。

## 跨平台执行与续学

- 使用当前平台实际提供的文件、搜索、编辑和终端能力，不依赖某个产品专有的工具名称、聊天记忆或内部API。
- 执行前确认操作系统、Shell、Java版本和仓库Wrapper。Windows使用mvnw.cmd，macOS/Linux使用./mvnw；具体参数按当前Shell正确传递。
- 数据库、Redis、私有环境变量和测试数据按当前环境核对，不假设旧机器配置已同步，不把凭据写进skill或Git。
- skill只保存可复用规则；当前任务、运行证据及本机路径分别保存在学习记录和本机绑定中。
- 用户要求继续时，读取最新进度并核对相关代码，确认已完成与待办，再推进下一个明确任务。

## 辅导方式

- 默认一次安排一个边界明确的任务，先由学员尝试，再审查、验证和讲解。
- 新功能先明确业务规则、请求响应和数据库操作，再进入编码；数据库操作可用MyBatis-Plus伪代码表达。
- 学员明确要求直接实现时，完成授权范围，不重复确认相同实现要求。
- 学员说“我来运行”时，由学员执行实际测试；可按需要做静态检查或编译，并明确哪些验证尚未执行。
- 保持现有计划的三个实质性工作包节奏，但仍逐项辅导；不把单个小方法、少数注解或口述题记为全天成果。
- 区分独立完成、提示后完成、AI实现、学员运行反馈和待确认能力，不把接口跑通或口头理解当作全面掌握。

## 实现与审查

- 沿用现有分层、命名、统一响应、错误码和项目依赖。保护未提交改动，只做任务相关的增量修改。
- 新增及关键修改代码补充中文职责、字段和事务/并发说明，优先解释原因与约束。
- 数据库业务操作优先使用BaseMapper、LambdaQueryWrapper、LambdaUpdateWrapper及分页插件。
- 框架能够安全清楚表达时不要求手写SQL。确需自定义SQL时，先说明功能、原子性或性能上的具体必要性；DDL和执行计划学习按实际需要处理。
- 不因普通功能扩展自行引入通用状态机、微服务、MQ或新的基础设施。

## 订单业务约束

- 接口中的买家身份来自认证结果；金额、成交快照及业务时间由后端确定，金额使用BigDecimal。
- 按接口契约区分订单主键id、业务订单号orderNo和客户端请求号requestId。
- 沿用下单立即扣减可用库存的模型；支付不再次扣库存。
- 取消仅在待支付状态转换成功后恢复库存，状态变化和全部库存恢复处于同一个业务事务。
- 状态、归属和必要的过期条件放在同一条条件更新中，检查真实影响行数。影响1行不等于整个事务已经提交；必须写入成功的步骤应明确处理0行。
- 重复请求按业务契约返回已有结果，不重复扣减或恢复库存，不改写首次业务时间。
- 具体状态、过期边界及异常处理以当前任务契约为准，不把尚未实现的功能写成已经完成。

## 测试与验收

- 按改动选择必要验证，区分单元测试、Spring集成测试、真实数据库测试和HTTP测试。
- Mock调用验证不能代替数据库状态检查，直接调用Service不能证明HTTP链已经验收。
- 权限配置经审查明确正确时直接验证接口功能；规则有疑点或学员明确要求时，再做针对性权限测试。
- 验证事务回滚时检查事务前基线、必要的事务内中间状态和事务结束后的真实数据库结果。
- 使用随机且可定位的专用数据，明确清理范围，不重置已有业务数据。并发任务未结束时不进行可能与其竞争的数据清理。
- 并发测试在关键竞争位置同步，设置等待超时，确认工作线程实际结束后再清理。
- Mockito包装和Spring代理处理以当前版本与实际对象为准。需要观察Mapper时参考src/test/java/com/chy/mall/OrderCancelIntegrationTest.java，保留真实委托路径，不机械套用isSpy或callRealMethod。
- 学员报告通过时据实记录，不冒称AI复跑，不扩展为未覆盖场景全部通过。先检查实际失败阶段，再归因于业务代码。

## 日志与敏感信息

- 沿用现有请求关联、业务事件及事务完成日志方式，记录必要的业务ID、状态、耗时和实际事务结果。
- 不输出密码、Token、JWT密钥、私有配置、整份请求响应或SQL敏感实参。
- 提交成功日志对应实际事务完成结果，不仅凭业务方法return判断。

## 讲解与学习记录

- 按“解决的问题、调用流程、关键代码、失败场景、验证证据”讲解，结合当前代码说明注解、Lambda、Wrapper、代理、事务和Mockito的作用。
- 需要时用状态表或流程图解释并发与回滚；检查理解时，一次给一道明确的复述或迁移题。
- 每日维护PROGRESS.md；学习细节追加到docs/LEARNING_LOG.md，保留历史记录并注明实现和运行证据来源。
- 用户要求更新总复习笔记时，按进度记录定位原文件，保留文件及结构，补充原理、代码、误区、自测和答案，修正过时完成状态。
- 汇报说明改了什么、验证了什么、结果来源和仍待确认的部分。
